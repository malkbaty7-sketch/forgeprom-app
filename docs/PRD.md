# PRD — Forgeprom Code Studio (v1.0.0-mvp)

## المشكلة

المستخدم العربي يصف فكرته بلغة حرة، فيولّد له مساعدو الكود نواتج ناقصة أو متضخمة: لا سياق، لا حالات إلزامية، لا معايير قبول، وكود زائد خارج النطاق.

## الحل

استوديو Android يحوّل الفكرة العربية الحرة إلى **موجه هندسي كامل** (12 قسماً) جاهز للنسخ في أي منصة توليد كود، مع افتراضات **معلنة** وأسئلة محدودة (≤3) بدل التخمين الصامت.

## المستخدم المستهدف

مطور أو صاحب فكرة عربي يريد ناتجاً احترافياً دون إتقان صياغة البرومبتات الإنجليزية.

## المتطلبات الوظيفية (MVP)

1. إدخال فكرة + هدف + تقنية → تحليل محلي (نية/ميزات/متطلبات/قيود/افتراضات/أسئلة ≤3).
2. اعتماد التحليل (قابل التحرير) → توليد برومبت 12 قسماً باللغة المختارة (AR/EN/DUAL).
3. فحص جودة (14 عنصراً، خصم 7 لكل ناقص) + إصلاح تلقائي عند الدرجة <70.
4. نقد واقتراح (نقاط قوة/نواقص/مخاطر).
5. مشاريع: إنشاء/تثبيت/أرشفة/حذف + محرر موجزات بعدادات.
6. تصدير TXT/MD/JSON + نسخ + مشاركة بترميز UTF-8.
7. تحليل صورة واجهة (سحابي اختياري بموافقة صريحة + إقرار «استلهام فقط»).
8. مفاتيح API مشفّرة؛ بوابة موافقة سحابة مرفوضة افتراضياً.

## مبادئ غير قابلة للتفاوض

- **الصدق:** لا ادعاء جاهزية قبل عمل فعلي؛ الحالات تُعرض كما هي.
- **الخصوصية:** لا يغادر محتوى الجهاز دون موافقة صريحة.
- **منع التضخم:** قيود صريحة ضد الكود الزائد في كل برومبت.
- **افتراضات معلنة:** لا تخمين بصمت.

## معايير القبول

- 8 اختبارات وحدة تمر لطبقة المجال (`gradle testDebugUnitTest`).
- `assembleDebug` ينجح في CI ويخرج APK.
- كل ميزة في FeatureRegistry بحالة حقيقية قابلة للتحقق.
